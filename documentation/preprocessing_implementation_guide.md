# FarmLite Preprocessing Implementation Guide

## What Phase 3 Built

Phase 3 built the reusable steps that prepare data for later machine-learning
experiments. It did not train a classifier or regressor.

The source is publisher-declared synthetic cattle data. The pipeline is useful
for an undergraduate demonstration, but its outputs must not be presented as
veterinary, nutritional, commercial, or scientifically validated guidance.

## Why Raw Data Is Never Edited

Raw data is the original evidence used by the project. Editing it would make
the work difficult to reproduce and could hide errors. FarmLite therefore
reads the CSV and creates logical views and small assignment manifests without
writing over either source dataset.

The validation command checks the primary CSV against its approved SHA-256
checksum. It does not normally load or merge the disease dataset.

## Canonical Column Names

Different systems use different names for the same field. For example, the CSV
uses `Age_Months`, the API uses `ageMonths`, and preprocessing uses the
canonical name `age_months`.

The canonical mapper reads only aliases approved in
`backend/flask_api/config/column_aliases.json`. It rejects ambiguous mappings
instead of guessing. Renaming a column does not change any of its values.

## Schema Validation

A schema is a description of the fields and values that are expected.
Validation checks:

- required columns;
- duplicate columns;
- numeric convertibility and finite values;
- hard-invalid values such as negative age or humidity outside 0–100;
- unknown categories;
- suspicious synthetic-data ranges;
- forbidden target or identifier leakage.

Three modes are available:

- `TRAINING_DATA` requires all selected features and the target;
- `INFERENCE_INPUT` requires only the approved request fields and no target;
- `TEST_FIXTURE` applies the same rules to small test data.

Warnings preserve suspicious rows. Hard-invalid findings make validation fail,
but no record is silently deleted.

## Cleaning and Quality Flags

The cleaner trims surrounding category whitespace, converts empty strings to
missing values, applies approved case/value formatting, and safely parses
numeric columns. It records each action with the source row, field, original
value, normalized value, severity, and action.

Unknown categories remain unknown. In particular:

- `Dry` is not converted to Early, Mid, or Late lactation;
- an unknown breed is not converted to Holstein or another known breed.

Rows are kept in their original order. Statistical outliers are reported, not
automatically deleted.

## Missing-Value Imputation

Imputation means filling a missing input with a value learned from available
training data. FarmLite defines:

- median imputation for numeric features;
- most-frequent imputation for categorical features;
- missingness indicators for optional numeric fields.

These rules live inside sklearn preprocessing pipelines. Their statistics
must be fitted using the training split only. Using the whole dataset would
let validation or test information leak into training.

## Categorical Encoding

Models need numbers rather than category text. `OneHotEncoder` creates a
separate binary indicator for each observed category without pretending that
categories have a numeric order.

`handle_unknown="ignore"` allows a later unseen category to transform without
crashing. Schema validation still produces a warning so the application can
explain that the value was unseen.

## Why Splitting Happens First

The 250,000 synthetic rows have one deterministic assignment:

- training: 175,000 rows (70%);
- validation: 37,500 rows (15%);
- test: 37,500 rows (15%).

The training set teaches future preprocessing statistics and models. The
validation set will support design and hyperparameter decisions. The test set
must remain untouched until those choices are complete, so it can provide a
less biased final synthetic-data evaluation.

The split uses seed 42 and preserves `Feed_Type` class proportions. The same
base assignment is available to all three future tasks.

## Out-of-Fold Preparation

Model 2 Design B will later use the feed category predicted by Model 1. If the
true same-row `Feed_Type` were used, Model 2 would receive the answer rather
than a realistic prediction.

Phase 3 assigns each training row to one of five deterministic folds. A later,
separately approved phase can use those folds to create out-of-fold Model 1
predictions. The current fold manifest contains assignments only—no labels
generated by a model and no predictions.

## Identifiers and Leakage

`Cattle_ID`, `Farm_ID`, dates, and direct row numbers may be retained for
traceability, but they are never model inputs. A model could memorize
synthetic identifiers or generated batches instead of learning a reusable
relationship.

Leakage also occurs when a model receives its own target, a same-record
outcome, or information that would not exist when a prediction is requested.
Leakage can make accuracy appear unusually high while producing a model that
fails outside the experiment.

## Feature Views

Model 1, Model 2 Design A, and Model 3 use this exact order:

1. `breed`
2. `age_months`
3. `weight_kg`
4. `lactation_stage`
5. `days_in_milk`
6. `previous_week_avg_yield_l`
7. `body_condition_score`
8. `ambient_temperature_c`
9. `humidity_percent`

Model 2 Design B adds `predicted_feed_type`. Its builder is disabled by
default and refuses to substitute true `feed_type`.

## Commands

Run these commands in PowerShell:

```powershell
cd D:\UOB\FarmLite\backend\flask_api
venv\Scripts\python.exe -m ml.preprocessing.validate_preprocessing
venv\Scripts\python.exe -m unittest discover -s tests -v
```

The existing virtual environment does not currently contain pytest. No package
was installed during Phase 3. If pytest is explicitly approved and installed
later, the equivalent command is:

```powershell
venv\Scripts\python.exe -m pytest
```

Inspect the main reports:

```powershell
Get-Content ml\reports\preprocessing_validation_report.md
Get-Content ml\reports\data_split_report.md
Get-Content ml\reports\data_split_summary.json
Get-Content ml\reports\feed_type_oof_fold_summary.json
Import-Csv ml\reports\data_split_manifest.csv | Group-Object split
Import-Csv ml\reports\feed_type_oof_fold_manifest.csv | Group-Object training_fold
```

There is intentionally no model-training command in this guide.
